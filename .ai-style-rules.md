# Existing implementation conventions

## Golden Files

- `training-store.js`: versioned storage validation and result objects; retain the storage contract.
- `session-ui.js`: canonical `S`, derived results, existing lifecycle and event wiring; add optional presentation hooks only.
- `app.js`: `PKG` content and native DOM helpers; preserve question IDs and event contracts.
- `feedback.js`: pure rule-based feedback boundary; preserve its outputs.

## Naming & State-Control Rules

- Native JavaScript, DOM, CSS, and existing helpers (`$`, `el`, `esc`); no framework.
- Source of truth is `S`; report data comes from `deriveResults`. UI view state is ephemeral and must not enter persisted schemas.
- Preserve current element IDs, radio name patterns and lifecycle handlers. Existing renderers own their generated nodes.
- New presentation code lives in `interface.js`, tokens and style overrides in `redesign.css`.
- Optional `window.TrainingUI` hooks coordinate presentation without replacing engine functions.
- Escape text inserted into HTML; use `textContent` for user strings. Storage failures remain visible.

## DONTs

- Do not change PKG, CSV, storage shape, scoring rules, or the existing 46 tests for a visual redesign.
- Do not replace working event handlers with duplicate engines or clone live learning nodes.
- Do not fabricate progress, records, user levels or learning time.
- Do not accumulate learning time while on home, in menus or historical reports.
- Do not silently replace an unfinished session when changing a home entry point.
