# 맞춤형 읽기 훈련

공개된 **소금은 어디에서 올까** Artifact의 지문과 문제를 유지하면서 저장·이어하기·결과·기록을 연결한 로컬 작업본입니다. 홈의 세 카드는 이제 서로 다른 영역별 활동으로 연결됩니다. **전체 과정 학습하기**는 어휘 → 지문 1(Stage 1·2 연속 개념 읽기 후 빈칸 채우기) → 독해 → 통합 리포트로 연결됩니다. 이전 통합 과정은 메뉴의 **기존 통합 학습**에서 계속 사용할 수 있습니다. 공개 Claude Artifact에는 변경 사항을 게시하지 않았습니다.

최신 화면은 토스 스타일을 참고한 `#F2F4F6` 회색 배경, 흰색 카드, `#191F28` 본문과 `#4E5968` 보조 문구를 사용합니다. 주요 동작은 `#1B64DA` 파랑으로 통일하고, 홈 진행 막대는 `#3182F6`을 사용합니다. 그라데이션과 카드 그림자가 없는 20px 둥근 카드 구성을 유지합니다. 유창성·어휘력·독해력 카드는 각각 옅은 Red·Mint·Blue 단색입니다. TDS 패키지를 도입하지 않았으며, 새 활동에 필요한 스타일만 `activity.css`로 확장합니다.

기본 흐름은 **홈 → 영역 선택 → 읽기·문제 풀이 → 결과 → 학습 기록 → 이어서 또는 다시 학습**입니다. 홈은 실제 저장 기록으로 누적 학습 시간, 오늘 완료한 영역, 최근 기록 3개를 표시합니다.

| 홈 훈련 카드 | 실제 활동 | 기본 채점 문항 수 |
|---|---|---:|
| 지문 1 · Red | Stage 1 탭 개념 읽기 → Stage 2 밑줄 따라 읽기 → 빈칸 5개·확신도 | 5개 빈칸 |
| 어휘력 · Mint | 오늘의 단어 카드 10개 → 원본 활용 5문항 → 낱말로 문장 만들기 2개 | 5 |
| 독해력 · Blue | 글 읽기 → 문단 리스트 탭 배치 → 기존 문단 구조 문제 → 연결 구조도 탭 배치 → 지문과 함께 내용 4문항 → 독해 개념 인출·핵심 문장·문장 뼈대·간추려쓰기 | 11개 채점 활동 |

어휘력은 **오늘의 단어** 카드 화면으로 시작합니다. 카드를 누르면 원래 패키지의 뜻·품사·예문이 열리고, 확인한 카드는 테두리와 `✓ 확인함`으로 구분합니다. `다음`으로 문제 풀이를 시작하고, 풀이 중 `단어 카드 다시 보기`로 돌아가도 현재 답안은 유지됩니다. 카드 확인 표시는 현재 화면 사용 중에만 유지되며 새로고침하면 초기화됩니다. 카드 학습 시간은 총 학습 시간에 포함하되 문제 응답 시간에는 포함하지 않습니다.

어휘의 고유 낱말은 기존 패키지의 **10개**입니다. 새 회차는 공개 Artifact의 뜻 고르기 1개·문맥 빈칸 2개·비슷한 말 1개·잘못 쓴 문장 1개를 질문·보기·정답 그대로 재사용합니다. 정오답과 관계없이 **활용 5문항**을 마치면 기존 서술형으로 넘어가며 학습 중 오답을 자동 재출제하지 않습니다. 기존 글짓기 2개는 각 칸에 내용만 입력하면 저장하는 점수 없는 자유 입력 연습입니다. 필수 낱말과 최소 10자 제한은 없습니다. 결과의 **5문항 정답률**을 확인한 후 필요하면 틀린 문제를 다시 풀 수 있습니다. 이전 32문항 회차와 자동 복습이 있는 회차·기록은 기존 방식 그대로 복원합니다. 원본 직접 수행과 검증 내용은 [어휘력 통합 보고서](VOCABULARY_INTEGRATION_REPORT.md)에 있습니다.

지문 1의 새 회차는 **Stage 1 → Stage 2 → 빈칸 채우기**로 구성합니다. 기존 Stage 3 읽기를 Stage 2로 바꾸고, 두 읽기 사이의 문제를 제외합니다. 두 읽기는 기존 `PKG.concept`의 중심 문장·뒷받침 문장과 소금 생산 과정 글을 그대로 사용합니다. Stage 1은 탭하여 어절을 읽고, Stage 2는 구절을 1.2초씩 밑줄 위에 표시합니다. 첫 읽기가 끝나면 다음 읽기로 이동하고, 두 번째 읽기가 끝나면 해당 글의 빈칸 5개와 확신도 입력으로 한 번만 이동합니다. 확신도 기본값은 `아마`이며 `확실`·`모름`도 선택할 수 있습니다. 각 빈칸을 따로 채점하므로 지문 1은 5개 빈칸, 전체 과정은 어휘 5 + 지문 1 빈칸 5 + 독해 14 = 24개 채점 항목입니다. 어휘 문장 만들기 2개와 독해 간추려쓰기는 점수 없는 연습입니다. 새 회차는 `fluencyConceptV2`/`courseConceptV3`를 사용하며, 이전 1·3단계와 중간 빈칸 회차 및 이전 객관식 회차·완료 기록은 원래 활동 목록과 점수로 복원합니다.

메뉴의 기존 통합 과정은 **어휘 → 개념·인출 → 읽기·진단 → 구조화·글쓰기 → 리포트** 순서를 유지합니다. 기존 과정과 영역별 과정의 진행 중 답안은 별도로 저장합니다. 영역별 회차를 교체할 때는 확인을 받고, 완료 기록은 유지합니다. 홈은 두 종류의 기록을 합쳐 표시합니다. 오늘 완료는 한국 시간 기준이며 오답만 재학습한 회차는 영역 완료로 세지 않습니다. 이전 통합 과정의 기록은 기존 단계 대응 규칙에 따라 반영합니다.

읽기 화면에는 **읽기 건너뛰기** 버튼이 있습니다. 지문 1은 시작 전이나 읽는 도중 다음 읽기 또는 마지막 빈칸 채우기로 넘어갈 수 있고, 지문 2의 글 읽기·개념 읽기는 다음 활동으로 넘어갑니다. 건너뛴 읽기는 별도 표시로 저장·복원하며 결과에 `건너뜀`으로 표시합니다. 읽기 완료 Stage와 읽기 속도로 계산하지 않으며, 문제 풀이와 채점은 그대로 진행합니다.

## 실행

Python 3로 정적 서버를 실행합니다. 앱 실행에는 Node.js나 npm 설치가 필요하지 않습니다.

```sh
cd reading-training
python3 scripts/serve.py
```

브라우저에서 [맞춤형 훈련 홈](http://127.0.0.1:4173/)을 엽니다. 진행 중 회차는 홈의 이어하기에서, 완료 회차는 이전 훈련 기록 또는 메뉴의 학습 리포트에서 확인합니다.

`dist/training.html`은 CSS 3개와 JavaScript 15개를 각각 하나의 인라인 스타일·스크립트로 합쳐 압축한 단일 파일입니다. [단일 HTML 작업본](http://127.0.0.1:4173/dist/training.html)으로도 실행할 수 있습니다. 저장 동작이 브라우저마다 다른 `file://` 직접 실행보다는 HTTP 실행을 권장합니다. 두 경로는 같은 origin이므로 같은 저장소를 사용합니다. Google Fonts를 받지 못하면 시스템 글꼴로 표시됩니다.

## GitHub Pages

빌드는 같은 완성본을 `dist/index.html`에도 생성합니다. Pages에는 `dist`의 내용만 담은 `codex/github-pages` 브랜치의 루트(`/`)를 게시합니다. 원본 코드·테스트·문서는 기본 소스 브랜치에 보관합니다.

변경 후에는 테스트와 빌드를 실행하고 소스 커밋을 푸시한 다음, 다음 명령으로 배포 브랜치를 갱신합니다. 강제 푸시는 사용하지 않습니다.

```sh
git subtree push --prefix=dist origin codex/github-pages
```

로컬 주소와 GitHub Pages는 서로 다른 origin이므로 학습 기록과 진행 중 답안은 각각의 브라우저 저장소에 따로 저장됩니다. 로컬 기록은 자동으로 업로드되거나 이전되지 않습니다.

## 검증 및 단일 파일 생성

Node.js 22.12+ 또는 24+와 Python 3가 필요합니다. jsdom은 테스트 전용 의존성입니다.

```sh
npm ci
npm run check
npm test
npm run build
```

이전 영역별 활동 구현 시 구문 검사, **전체 테스트 97/97**, 단일 HTML 빌드를 통과했습니다. 기존 회귀 46개와 기존 UI 통합 13개를 유지하고 콘텐츠 6개·영역별 엔진 19개·화면 통합 13개를 추가했습니다. 원본 `PKG`와 기준 파일 6개의 해시도 동일합니다. 실제 브라우저에서 세 영역 완료, 오답 재출제, 새로고침 후 선택 복원 및 390/820/1280px 화면의 가로 넘침 없음을 확인했습니다. 세부 증거와 검증 범위는 [영역별 활동 구현 보고서](ACTIVITY_FLOW_REPORT.md)를 참고하세요.

이전 3단계·객관식 통합은 [Artifact 전체 학습·Stage 3 통합 검증](FLUENCY_INTEGRATION_AUDIT.md)에 정리합니다. 이전 객관식 전환은 [객관식·1.2초 표시 검증](FLUENCY_CHOICE_UPDATE.md)에 있습니다. 이전 단계는 [Stage별 퀴즈·밑줄 읽기 검증](FLUENCY_ROUNDS_FIX.md)에 있습니다. 최초 통합 검증은 [읽기 유창성 통합 보고서](FLUENCY_INTEGRATION_REPORT.md)에 있습니다. 이전 순서로 시작한 회차는 `이전 방식`으로 표시해 그대로 이어 볼 수 있고, 새 회차부터 각 Stage 뒤 퀴즈가 나오는 흐름을 적용합니다. 이전 표시 속도로 시작한 회차는 `이전 속도`로 구분하며, 새 회차의 Stage 2·3은 모두 1.2초 간격이며 문장 순서 문제는 객관식 과정 확인 문제로 바뀌었습니다.

어휘 통합 후에는 구문 검사·전체 테스트 **121/121**·단일 HTML 빌드를 통과했습니다. 직접 풀이의 80% 첫 결과, 100% 오답 복습 결과, 새로고침 복원 및 문장 초안 저장은 [어휘력 통합 보고서](VOCABULARY_INTEGRATION_REPORT.md)를 참고하세요.

## 상태 및 저장 계약

- `trainingSession`: `version: 1`, `packageId: salt-v1`, 회차 ID, 단계·하위 화면, 마지막 입력 위치, 답안·확신도·문장 배치·요약, 제출 여부, 시간, 파생 결과.
- `trainingHistory`: 완료 회차 배열. 각 항목에 version·ID·완료 시각·시간·결과·세션 스냅샷을 저장합니다. 같은 ID는 중복 추가하지 않습니다.
- `areaTrainingSession.v1`: 영역별 `version: 1` 세션. 영역·활동 큐·현재 위치·선택/제출 답안·읽기 시간/위치·전체 시간·복습 원본 ID를 저장합니다.
- `areaTrainingHistory.v1`: 영역별 완료 세션 스냅샷. 기존 저장 키와 분리하며 같은 ID는 중복 추가하지 않습니다.
- 결과는 저장된 답안에서 다시 계산합니다. 제출된 답안은 잠그며 다시 풀기는 새 ID를 만듭니다.
- 입력과 이동 때 저장합니다. 기존 과정의 시간은 5초 간격, 새 영역별 과정은 학습 중 1초 간격으로 저장합니다. 이탈·숨김 이벤트에도 저장을 시도합니다. 갑작스러운 프로세스 종료는 마지막 시간 갱신 일부가 누락될 수 있습니다.
- 영역별 학습은 새로고침 후 선택 답안, 문단 순서, 구조도 배치, 제출 상태, 오답 재출제 큐, 읽기 시간과 자동 읽기 위치를 복원합니다. 자동 읽기는 계속 읽기를 눌러 재개합니다.
- 홈·리포트·기록·메뉴·재개 및 확인 대화상자, 숨겨진 탭의 시간은 학습 시간에 더하지 않습니다. 포인터 기반 읽기 지표는 시선 측정값이 아닙니다.
- 완료 기록 저장이 실패하면 새 회차로 덮어쓰지 않고 결과를 유지합니다. 저장 공간을 확보한 뒤 완료/재학습 동작을 다시 시도할 수 있습니다.
- 영역별 완료 기록은 200개까지 보관합니다. 한도를 넘으면 기존 기록을 삭제하지 않고 경고하며 현재 결과를 유지합니다. 손상된 영역별 완료 기록에도 새 기록을 덮어쓰지 않습니다. 기록 내보내기·한도 관리 화면은 아직 없습니다.
- 없음·깨진 JSON·부분 데이터·미지원 버전은 안내와 안전한 기본값으로 처리합니다. 지원하지 않는 원본 데이터를 영구 백업/마이그레이션하는 기능은 없습니다. 복구 후 새 진행 저장은 현재 키를 교체할 수 있습니다.

## 범위와 한계

고정된 한 개 지문과 기존 어휘 10개를 사용합니다. 새 어휘 회차는 원본 5문항을 사용하며 이전 32문항 회차는 이어하기 호환을 위해 유지합니다. 문단 순서·구조 문제는 기존 네 문단에서 구성했습니다. 낱말 포함·글자 수 등의 규칙을 실제 AI의 의미·문맥 평가로 표시하지 않습니다. 계정·서버 동기화·동시 탭 충돌 조정은 없고, 같은 브라우저 origin의 마지막 저장을 사용합니다. 브라우저 데이터 삭제 시 기록도 지워집니다.

표시된 사용자명과 학년은 현재 데모의 고정 정보이며 로그인이나 자동 레벨 산정 기능은 없습니다. 음성 인식·발음 평가·실제 시선 추적은 없습니다. 새 지문 1의 표시 속도는 `fluency-concept-content.js`의 설정값으로 관리하며 학습자별 속도 설정 화면은 없습니다. 읽기 속도 수치는 탭·화면 표시 시간을 기준으로 계산합니다.

첨부 어휘 CSV는 아직 실행 흐름에 연결하지 않았습니다. 이번 기능과 검증 경계는 [영역별 활동 구현 보고서](ACTIVITY_FLOW_REPORT.md), CSV 구조는 [CSV 자료 검토](CSV_DATA_NOTES.md)에 정리합니다. 과거 단계의 기록은 [Artifact 감사](ARTIFACT_AUDIT.md), [기능 안정화 결과](IMPLEMENTATION_REPORT.md), [리디자인 결과](REDESIGN_REPORT.md), [토스 스타일 결과](TOSS_THEME_REPORT.md)에 있습니다. 스타일 확장 시 [디자인 시스템](DESIGN_SYSTEM.md)을 참고하세요.

## 독해력 READIN 방식 검증

지문 2은 기존 「소금은 어디에서 올까」로 지문 읽기 → 정밀검사(문단별 핵심 문장 4개 확인) → 이해도 테스트 7문항(사실적 이해 5·추론적 이해 2) → 구조화·글쓰기 순서로 진행합니다. 정밀검사는 전체 지문에서 문단별 핵심 문장을 하나씩 선택하고, 정답은 파랑·맞게 고른 문장은 초록·잘못 고른 문장은 빨강으로 표시합니다. 사실적 이해 5문제와 추론적 이해 2문제를 마친 뒤에 처음·중간·끝으로 구조화합니다. 각 이해도 문항의 채점 결과에는 근거 문장 번호와 원문을 표시합니다. 읽은 시간·속도·역행·체류 포착률·문단별 체류 시간은 실제 저장한 읽기 기록으로 보여주며, 포인터·터치 기준의 데모 대체 지표임을 안내합니다. 기록이 부족할 때는 병목 문단을 추정하지 않습니다. 선택한 문장은 색과 분류 이름으로 표시하고, 아래에 분류 결과를 모아 보여줍니다. 정밀검사에서는 읽은 시간과 핵심 문장 선택 결과를 표시합니다. 문단 순서 맞추기, 문단 구조 객관식, 문단 연관성 연결은 새 학습에서 제외하며, 구조화는 기존 처음·중간·끝 문장 뼈대를 사용합니다. 새 지문 2에서는 개념 읽기·인출을 반복하지 않습니다. 이전에 시작한 회차는 답안과 시간을 보존하여 해당 순서로 이어하고, 새 회차부터 변경된 순서를 적용합니다. 완료 기록은 원래 결과로 보관합니다. 어휘 서술형과 간추려쓰기는 기존 내용을 유지합니다.

이해도 확인은 원본의 질문·보기·정답을 사용하며 정확히 7문항입니다. 넓은 화면은 지문과 문제를 나란히 표시하고, 모바일은 같은 문제 화면에서 지문 패널을 열고 접으며 독립적으로 스크롤합니다. 문제 이동·채점 시 같은 지문과 스크롤 위치를 유지합니다. 이해도 확인 전용 진행률과 전체/사실적/추론적 결과를 구분해서 표시합니다. 독해 결과에는 정밀검사 1개, 이해도 확인 7개, 문장 뼈대 1개가 포함되어 총 9개 채점 활동입니다. 핵심 문장과 뼈대는 각 전체 배치를 한 활동으로 채점하고 상세 결과에서 4개·5개의 위치 정확도를 제공합니다. 간추려쓰기는 정답률에서 제외합니다. 완료된 이전 회차와 기존 전체 과정 기록은 원래 구성과 점수로 복원됩니다.

수정 전·후 직접 풀이, 사진과의 비교, 저장·이어하기·오답 복습 회귀 결과는 [독해력 검증 보고서](READING_INTEGRATION_REPORT.md)에 있습니다. 어휘·유창성의 활동 데이터와 기존 과정의 저장 키는 변경하지 않았습니다.


### 전체 학습 분류 후 독해력 추가 통합

사용자가 지정한 Claude 아티팩트와 로컬의 전체 과정·기존 통합 학습을 각각 리포트까지 실제로 풀고 목적과 수행 동작을 비교했습니다. 중심·뒷받침 문장 개념 읽기 및 인출·확신도, 문단별 핵심 문장 찾기, 처음·중간·끝 문장 뼈대, 간추려쓰기를 독해에만 추가했습니다. 인출의 바닷물·염전·증발 3칸과 유창성에 이미 있는 추론 2문항은 반복하지 않습니다. 원본 통합 학습도 유지합니다. 상세 분류·제외 근거·테스트 결과는 [전체 학습 분류 보고서](LEARNING_CLASSIFICATION_REPORT.md)에 있습니다.

새 독해 회차는 readingReadinV3/courseReadingReadinV3를, 현재 전체 과정은 courseConceptV3를 사용합니다. 이전 V1/V2와 모든 예전 영역·전체 과정 카탈로그는 원래 답안·목록·점수로 복원됩니다. 기존 내용 객관식 4문항의 자리에서 7문항으로 교체하며, 이후의 개념 인출과 문장 선택은 기존 순서를 유지합니다. 간추려쓰기는 기존 최소 40자, 150자 안팎 가이드와 TrainingFeedback의 규칙 기반 지표를 사용합니다. 의미·문법·요약 충실도 평가나 외부 AI 호출은 없습니다.

7문항 교체·브라우저 전체 진행·저장/이어하기·유형별 채점·오답 복습 검증은 [이해도 확인 검증 보고서](READING_COMPREHENSION_REPORT.md)에 있습니다. 실제 Chrome 회귀 검증은 Playwright가 있는 환경에서 `node scripts/test-reading-browser.cjs`로 실행합니다. 로컬 서버 기본 주소는 `http://127.0.0.1:4173/`이며 `QA_BASE_URL`로 바꿀 수 있습니다.

## 실행 성능 최적화

홈·메뉴·읽기 시작 전에는 타이머가 반복 저장하지 않습니다. 영역별 학습의 읽기 위치는 100ms 간격으로 계산하지만, 화면은 표시 내용이 바뀔 때만 갱신합니다. 답안 변경 즉시 저장과 학습 중 1초 시간 저장, 실패 후 재시도와 이전 회차 호환은 유지합니다.

`npm run build`는 esbuild로 압축한 단일 HTML을 생성합니다. npm 의존성 없이 읽기 쉬운 파일을 만들려면 `python3 scripts/build.py --no-minify`를 사용할 수 있습니다. `npm start` 또는 `python3 scripts/serve.py`는 원본 파일의 병렬 요청을 처리하는 미리보기 서버를 실행합니다.

최종 테스트 188개와 원본·압축본의 Chrome 전체 과정·새로고침 복원을 통과했습니다. 동일한 기능 기준 HTML 크기는 342,651B에서 253,498B로 26.0% 감소했습니다. 측정 범위와 상세 결과는 [최적화 검증 보고서](OPTIMIZATION_REPORT.md)에 있습니다. 반복 작업 측정은 `npm run benchmark`, 브라우저 검증은 Playwright가 있는 환경에서 `npm run test:browser` 및 `node scripts/test-optimization-browser.cjs`로 실행할 수 있습니다.
